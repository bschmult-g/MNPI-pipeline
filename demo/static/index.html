Reinforcement Learning Architecture v2.0

How Reinforcement Learning & Causal Attribution Work

Eliminating the dual dilemma of autonomous compliance: preventing catastrophic insider trading leaks while eradicating hyper-conservative false alarms on verified public news.

⚖️

1. Multi-Objective Reward Shaping

The Decision Authority Arbiter is scored on a multi-term reward model: rewarding correct leak neutralization while heavily penalizing unredacted dissemination (λveto = -10.0) and false-positive over-blocking (Rfp = -4.0).

🔍

2. Causal Attribution Engine (LOO)

Counterfactual Leave-One-Out (LOO) ablation isolates sensitive data signals (Sinfluence) from prompt context (U). Multi-leak cluster ablation resolves causal overdetermination.

🚀

3. DPO Margin Filtering (ΔR ≥ 2.5)

Direct Preference Optimization pairs (ywin, ylose) are filtered by minimum reward margin to guarantee high-leverage fine-tuning stability and eliminate noisy feedback.

The Compliance Reward Formula

Mathematical Objective Function
Rtotal = +1.00 + (-10.00) · 𝕀(Veto) + ∑ wk · CodePenalty(Ck) - 2.00 · Sinfluence - (-4.00)
Rtask = +1.0 Task Baseline

Execution reward awarded for producing structured judicial rationale, applying the 4 legal criteria, and generating actionable routing directives.

λveto = -10.0 Catastrophic Veto

Triggered whenever actual Material Non-Public Information is present in the source communication and the agent attempts to approve direct release.

Rfp = -4.0 Anti-Conservative Bias

Fixes "Paranoid Agent" syndrome: Heavily penalizes the model if it blocks or redacts verified public news wires, SEC filings, or routine immaterial chatter.

-γ · Sinfluence (γ = 2.0) Causal Penalty

Penalizes decisions where confidential insider intelligence drove the communication. Drops to zero when sensitive tokens are properly redacted or blocked.

∑ wk · CodePenalty(Ck) Machine Verification Codes

Standardized machine codes ensure granular, auditable evaluation across all 4 legal criteria:

MAT_01_MARKET_MOVING_MA (-3.0) MOSAIC_02_CONFIRMED_NON_PUBLIC (-2.0) DUTY_01_EXPLICIT_SECRECY_MARKER (-2.5) HARM_01_FRONT_RUNNING_EXPOSURE (-3.0) MAT_CLEARED_DE_MINIMIS (+1.0) MOSAIC_01_VERIFIED_PUBLIC_WIRE (+1.5) DUTY_CLEARED_EXTERNAL_SOURCE (+1.0) HARM_CLEARED_BENIGN (+1.0)

Causal Attribution Engine & Counterfactual Ablation

Leave-One-Out (LOO) v2.0

⚡ Hierarchical Gating Rule (Latency Optimization)

Running LLM ablations on every communication adds token latency and API cost. We implement a confidence pre-filter:

  • Sfull < 0.40: Cleared as public / benign. Ablation skipped (saves ~65% latency).
  • Sfull > 0.85: Violation is decisively certain. Ablation skipped to conserve cost.
  • 0.40 ≤ Sfull ≤ 0.85: Borderline Confidence Zone. Triggers deep counterfactual ablation.

🧩 Multi-Leak Causal Overdetermination

If a leaked document contains both an internal codename ("Project Titan") and an acquisition value ("$2.4B"), single-token LOO fails because masking either token leaves the other active (producing an artificially low ΔS).

Sjoint = P(Violation | Prompt + ℂ) - P(Violation | Prompt + ∅)

When individual deltas are masked but cluster ablation drops violation to zero, the engine flags is_overdetermined = True and confirms causal dominance.
